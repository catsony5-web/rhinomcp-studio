# 벽과 바닥 슬래브 도구

`create_wall`, `create_floor_slab`은 좌표에서 **Rhino의 닫힌 Brep 한 개**를 생성합니다. BIM 벽/바닥 타입, 재료층, 자동 벽 접합, 편집 가능한 매개변수 이력은 포함하지 않습니다. 모든 길이는 현재 문서 단위이고 체적은 문서 단위의 세제곱입니다. 밀리미터 예제를 미터 문서에 그대로 실행하면 크기가 달라지므로 먼저 `get_document_summary`로 단위를 확인하세요.

`layer`는 **이미 있는 레이어의 전체 경로**(`Architecture::Walls`) 또는 GUID입니다. 생략하면 현재 레이어를 사용하며 레이어를 새로 만들지 않습니다. `name`은 선택입니다. 같은 호출을 반복하면 별도의 객체를 다시 생성합니다.

## 직선 벽 `create_wall`

- `start`, `end`: `[x,y,z]` 형식의 수평 중심선 양 끝. Z 차이가 문서 절대공차 이내이면 `start.z`에 맞춥니다.
- 로컬 X는 start → end, 로컬 Y는 위에서 봤을 때 그 방향의 **왼쪽**입니다. 두께는 중심선에서 로컬 Y 양쪽으로 `thickness / 2`씩 배치합니다.
- `height`는 기준선에서 월드 +Z 방향 높이입니다. 기울어진 기준선은 지원하지 않습니다.
- `openings`: `{offset, width, bottom, height}` 배열입니다. `offset`은 start에서 X 방향 거리, `bottom`은 벽 밑면에서 개구부 밑면까지 높이입니다. `bottom=0`은 문, 양수는 창으로 처리하며 벽 두께 전체를 관통합니다.
- 높이·두께·기준선 길이·개구부 크기는 문서 절대공차보다 커야 합니다. 개구부는 벽 양 끝과 상단에 공차보다 큰 여유가 있어야 합니다. 양수인 `bottom`도 공차보다 커야 합니다. 개구부끼리 겹치거나 접촉할 수 없으며 공차보다 떨어져야 합니다. 상단이 열린 홈은 지원하지 않습니다.

밀리미터 문서 예제(문 1개, 창 1개):

```json
{
  "start": [0, 0, 0],
  "end": [6000, 0, 0],
  "height": 3000,
  "thickness": 200,
  "openings": [
    {"offset": 800, "width": 900, "bottom": 0, "height": 2100},
    {"offset": 3000, "width": 1500, "bottom": 900, "height": 1200}
  ],
  "name": "검증_문창벽"
}
```

예상 체적은 `(6000×3000 − 900×2100 − 1500×1200)×200 = 2,862,000,000 mm³`입니다. 외곽 범위는 X=0..6000, Y=-100..100, Z=0..3000입니다. 축 검증용으로 start=`[1000,2000,0]`, end=`[1000,8000,0]`로 바꾸면 X=900..1100, Y=2000..8000이고 local Y=`[-1,0,0]`이어야 합니다.

## 바닥 `create_floor_slab`

- `outer`: 순서대로 나열한 외곽 polygon의 `[x,y,z]` 정점 배열입니다.
- `holes`: 선택적인 구멍 polygon 배열입니다. 외곽/구멍 모두 시계·반시계 방향을 허용하고 마지막에 시작점을 반복해도 됩니다.
- 모든 정점은 수평 XY 평면에 있어야 합니다. Z 차이가 공차 이내인 점은 `outer[0].z`에 투영합니다.
- **`outer[0].z`가 슬래브 상단입니다.** 양수 `thickness`만큼 월드 **−Z**로 내려갑니다.
- 정점은 최소 3개이고 각 변 길이는 공차보다 커야 합니다. 자가교차·자기접촉·면적 퇴화·경계 접촉을 거부합니다. 구멍은 외곽 안에 완전히 들어가야 하며 서로 교차·접촉·중첩 포함 관계가 없어야 합니다. 곡선 경계는 지원하지 않습니다.

밀리미터 문서 예제:

```json
{
  "outer": [[0,0,3000],[6000,0,3000],[6000,4000,3000],[0,4000,3000]],
  "holes": [[[1000,1000,3000],[2000,1000,3000],[2000,2000,3000],[1000,2000,3000]]],
  "thickness": 200,
  "name": "검증_개구슬래브"
}
```

예상 상단/하단은 Z=3000/2800이고 체적은 `(6000×4000 − 1000×1000)×200 = 4,600,000,000 mm³`입니다. 구멍은 전 두께를 관통해야 합니다.

## 결과 검증과 실패 처리

중간 profile과 extrusion은 메모리에서 만듭니다. 닫힌 planar profile의 홀 개수를 확인한 뒤 extrusion을 생성하고, 유효성·닫힘·manifold·바깥 방향·naked/nonmanifold edge 0개·체적을 확인한 다음 문서에 추가합니다. 벽은 문을 외곽의 홈으로, 창을 inner loop로 처리하므로 문서 객체를 절삭하거나 삭제하지 않습니다. 삽입 이후 예외가 생기면 이번에 삽입한 객체를 삭제합니다.

응답의 `id`/`result_ids`는 생성된 GUID입니다. `geometry_health`에 검사 결과, `volume`/`expected_volume`/`volume_error`/`volume_tolerance`에 체적 비교가 들어갑니다. 허용 체적 오차는 `max(예상체적×1e-8, 표면적×문서절대공차)`입니다. 커널 검사 실패는 도구 오류로 전파됩니다.

실제 Rhino 8에서 위 예제를 실행한 뒤 반환 GUID로 `analyze_objects`, `measure_objects`를 호출해 체적과 solid 상태를 독립 확인하고 Perspective/Top/Front에서 개구부와 방향을 확인하세요. 축 회전 예제, 구멍 없는 슬래브, 오목한 외곽, 반대 winding, 두 개의 분리된 홀도 확인 대상입니다.

거부 검증: 벽의 겹친 개구부/상단까지 열린 개구부/다른 Z 기준선, 슬래브의 나비넥타이 자가교차 외곽/외부 홀/중첩 홀/경계에 닿는 홀/비평면 점/공차 이하 변을 각각 실행하고 객체 개수가 증가하지 않는지 확인합니다.

`server/tests/test_architecture.py`는 Python 입력 검증, JSON 계약, 전달값과 오류 전파를 확인하는 단위 테스트입니다. **mock 응답은 Rhino 기하 커널 검증 결과가 아니며**, 해당 테스트 통과만으로 Windows/macOS의 실제 Rhino 실행 검증을 완료했다고 판단하지 않습니다.
